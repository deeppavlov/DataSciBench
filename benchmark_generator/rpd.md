# Рабочий Проектный Документ (RPD) - Benchmark Generator

Этот документ предназначен для ИИ-агента для глубокого погружения в логику и структуру модуля генерации задач.

## Структура директорий и их роли

### 1. `/scripts` — Главная точка входа
Здесь находятся bash-скрипты, которые конфигурируют среду и запускают пайплайны. Это **единственный источник истины** для настроек рантайма.
- **`run_standard.sh` / `run_code_mode.sh`**: Быстрые обертки для запуска соответствующих Python-пайплайнов (`pipeline_standard.py` и `pipeline_code_mode.py`).

**Актуальная конфигурация (из скриптов):**
- **Модель**: `gemini-3-flash-preview` (через `BENCH_GEN_LLM_MODEL`).
- **API Base**: `https://generativelanguage.googleapis.com/v1beta/openai/` (Google AI Studio OpenAI-compatible).
- **Ключ**: Задается через `OPENAI_API_KEY` — из окружения либо из файла `.env` в корне проекта (см. `.env.example`).

### 2. `/core` — Инфраструктура
- **`llm.py`**: Клиент на базе библиотеки `openai`, адаптированный под работу с Gemini. Поддерживает структурированный вывод через Pydantic.
- **`mcp_tools.py`**: Логика взаимодействия с MCP-серверами. Отвечает за:
  - `discover_tools`: Опрос серверов.
  - `generate_api_doc`: Создание документации API для системного промпта.
  - `generate_wrapper_module`: Создание файла `_mcp_tools.py`, который позволяет решению вызывать инструменты.
- **`config.py`**: Pydantic Settings. Использует префикс `BENCH_GEN_`.

### 3. `/tools` — Атомарные инструменты
- **`generate_tasks.py`**: Создает заготовки (папку задачи, `prompt.md` и `input_data.py`).
- **`solve_task.py`**: Самый сложный компонент. Генерирует `solution.py` и `metrics.py`, а затем **выполняет** их для создания GT.
- **`pack_task.py`**: Переносит финальные файлы в структуру основного бенчмарка.

### 4. `/pipelines` — Оркестрация на Python
- **`pipeline_standard.py`**: Интерактивный процесс для задач на базе статического `code_base.txt`.
- **`pipeline_code_mode.py`**: Процесс для задач, использующих динамические MCP-инструменты.

## Жизненный цикл задачи (Технические детали)

### Генерация и подготовка
1. **`prompt.md`**: Основное описание задачи, которое видит будущая тестируемая модель.
2. **`input_data.py`**: Если задача требует внешних данных, этот скрипт **должен быть запущен** до решения. Он создает файлы (CSV, JSON и др.) прямо в директории задачи.

### Решение и Ground Truth (GT)
При запуске `solve_task.py`:
1. Создается папка `gt/` внутри директории задачи.
2. Генерируется **`solution.py`**.
3. Решение запускается **внутри `gt/`**. Все файлы, создаваемые решением (графики, модели), попадают только туда.
4. Генерируется **`metrics.py`**. Он содержит функции, проверяющие артефакты в `gt/`.
5. Генерируется **`chat_log.txt`** — содержит весь диалог с моделью-генератором (полезно для отладки "галлюцинаций" генератора).

### Code Mode и MCP
В этом режиме задача строится вокруг набора доступных инструментов.
- Конфигурация инструментов — `resources/mcp_servers.json`.
- После запуска пайплайна в `output/` (или папке задачи) появляется **`_mcp_tools.py`**.
- Решение (`solution.py`) автоматически импортирует этот модуль, чтобы взаимодействовать со средой.

## Отладка и решение проблем
- **Таймауты**: Ограничены `BENCH_GEN_CODE_TIMEOUT` (по умолчанию 300с). Если решение падает по таймауту, проверь нагрузку на систему или сложность задачи.
- **Ошибки импорта**: Часто связаны с `PYTHONPATH`. Скрипты в `/scripts` обычно добавляют необходимые пути (например, к `src` проекта).
- **Сломанные метрики**: Если `metrics.py` падает, изучи `verify_log.txt` и `chat_log.txt`. Метрики генерируются LLM на основе вывода выполнения решения, поэтому ошибка в решении часто влечет ошибку в метриках.
