# Рабочий Проектный Документ (RPD) - DataSciBench

Этот документ предназначен для быстрого погружения ИИ-агента в контекст проекта при последующих сессиях.

## Суть проекта
**DataSciBench** — это бенчмарк для языковых моделей (LLM) и агентов, сфокусированный на решении задач по Data Science (построение предиктивных моделей, анализ данных, обучение нейросетей и т.д.). В его основе лежит сильно кастомизированный фреймворк **MetaGPT**.

## Структура директорий
- `/MetaGPT` — ядро фреймворка MetaGPT. Проект использует собственную локальную версию MetaGPT, которую необходимо устанавливать через `pip install .` из этой папки.
- `/src` — исходный код логики бенчмарка (схемы, утилиты, эвалюаторы для проверки кода, сгенерированного LLM).
- `/role` — содержит кастомные роли агентов для MetaGPT, в частности `sci_data_interpreter` (Science Data Interpreter), который генерирует и выполняет код.
- `/experiments` — скрипты запуска экспериментов (генерация кода агентами и их выполнение). Основная точка входа — `run_examples.py`.
- `/evaluations` и `/evaluation_results` — скрипты для проверки результатов выполнения задач (успешность, время, затраты токенов, ошибки) и вычисления финальных метрик.
- `/data` — данные для задач (фреймы данных, промпты), используемые агентами при тестировании.
- `config2.yaml` (и аналоги в `MetaGPT/config/`) — файлы конфигурации моделей (API ключи, базовые URL для обращения к LLM, включая локальные модели через Ollama).

## Основные команды запуска (из корня DataSciBench)
**Запуск всех экспериментов:**
```bash
python -m experiments.run_examples
```

**Запуск конкретной задачи (например, dl_0):**
```bash
python -m experiments.run_examples --task_id dl_0
```

**Проверка сгенерированных результатов:**
```bash
python -m evaluations.check_result --model_id all
```

**Запуск оценки (Evaluation):**
```bash
python -m experiments.evaluate --task_id all --model_id <имя_модели>
```

## Ключевые особенности и подводные камни
- Проект активно использует системные переменные окружения и конфигурационные файлы YAML для подключения к моделям. Важно следить за тем, какой конфигурационный файл читается (`~/.metagpt/config2.yaml` или локальный `config2.yaml`).
- Агенты генерируют код и выполняют его локально. Если возникают ошибки выполнения (например, нехватка библиотек), их нужно устанавливать в текущее окружение.
- Для глубокого погружения в то, как агент решает задачи Data Science, смотри файлы в директории `role/` и `src/evaluator/`.
